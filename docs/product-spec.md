# Jenkins一键部署助手需求规格

## 项目启动信息

- **项目类型**：Windows 桌面运维工具
- **目标用户**：没有开发经验的项目实施人员
- **技术栈**：Java 21、JavaFX 21、Maven、Jenkins HTTP API、WinSW
- **终极功能**：用户双击打开软件，完成本机 Jenkins Agent 接入后，只需选择项目与生产目录即可创建前后端独立 Job 并完成首次部署。
- **本轮范围**：Job 自动触发与监控、失败分类、自定义 Pipeline、Java/.NET 10 WinSW 后端服务、IIS 角色/站点/反向代理自动配置及单元测试。
- **不在本轮**：直接操作真实生产 Jenkins、实机安装验收、HTTPS 证书签发、数据库迁移。

## 固定行为

1. 首次启动顺序：主机检测 → Jenkins 连接 → Agent 命名 → Java/agent.jar/WinSW 准备 → Windows 服务 → WebSocket 上线验证。
2. Agent 未验证在线时，项目部署操作不可用。
3. 凭据可明文保存在 `%ProgramData%\JenkinsDeployTool\config.env`，不显示、不记日志、不进诊断包。
4. 前后端分别生成 `<project>-frontend` 与 `<project>-backend` Job。
5. Gerrit 事件、分支匹配方式、分支规则和 SCM 轮询可由用户选择并同步到 Jenkins；默认值为 `Ref Updated`、`Plain: refs/heads/dev`、SCM 轮询关闭。
6. Gerrit 构建优先使用 `GERRIT_REFNAME`/`GERRIT_REFSPEC` 与 `GERRIT_NEWREV`/`GERRIT_PATCHSET_REVISION` 锁定触发版本。
7. Gerrit 地址固定为 `https://gerrit.example.com/`，API 使用软件内置固定账号；员工不能在界面替换账号。
8. 用户输入 Gerrit 项目名后调用 `GET /a/projects/{project-name}` 自动校验并生成仓库地址。
9. `windows-amd64` 软件包内置 WinSW v2.12.0 x64，运行时从软件资源目录复制到所选磁盘，不访问 GitHub，也不提供用户输入框。
10. 发布目录和 ZIP 必须带版本号；根目录显示 `Jenkins一键部署助手.exe` 和专用 `diagnostics` 文件夹，内部 Java 启动器放在资源目录并使用通用名称。
11. 诊断文件默认写入当前版本软件解压目录内的 `diagnostics` 文件夹，不再写入系统盘的 `%ProgramData%`。
12. 软件显示全部可用本地磁盘的可用/总容量，不默认选 C 盘；用户必须选择安装盘后才能配置 Agent。
13. Agent、Java Runtime、WinSW、日志和工作目录固定写入所选盘的 `JenkinsDeployTool\agent`，小型共享配置文件仍放在 `%ProgramData%`。
14. 发生错误时，错误弹窗和主窗口底栏都必须提供“导出诊断”入口，诊断文件写入当前版本目录的 `diagnostics` 文件夹。
15. Jenkins 与 Gerrit 使用默认公共 CA 加指定公司内部根 CA 的组合信任，保持 HTTPS 主机名校验，禁止 trust-all。
16. Jenkins 节点通过核心 XML 创建接口提交，避免依赖 Jenkins 网页表单的内部 JSON 绑定；WebSocket 由本地 Agent 启动参数启用。
17. Jenkins 返回异常状态时，普通界面只显示可执行的中文提示；导出的诊断文件额外记录经清洗、截断和凭据脱敏后的服务器响应正文。
18. 右侧主内容区在部署表单超过窗口高度时必须纵向滚动，禁止横向滚动；顶部栏、左侧步骤栏和底部诊断栏保持固定，并支持鼠标滚轮、触控板及键盘滚动。
19. 项目识别必须扫描用户所选根目录及其一级子文件夹，不依赖 `frontend`、`backend` 等固定目录名；前端标志为 `package.json`，Java 后端标志为 Maven/Gradle 构建文件，.NET 后端标志为 `.sln`、`.slnx` 或 `.csproj`。
20. 项目选择区必须在打开目录选择器前说明所需源码文件；若检测到 `dist`、`.jar` 或 `.dll` 等成品而没有源码构建文件，必须明确提示用户改选源码根目录。
21. 前后端 Job 每次构建先清理工作区，再从 Gerrit 拉取事件对应版本并重新编译；手工执行时使用所选 Plain 分支，非 Plain 规则回退到 `refs/heads/dev`，不直接部署用户选择目录中的本地产物。
22. 左侧导航必须对应三个独立页面：连接本机、选择项目、创建部署；当前步骤高亮，完成步骤可返回，未满足前置条件的步骤禁用。
23. Agent 验证在线后自动进入“选择项目”；项目识别成功后自动进入独立的“创建部署”，禁止把第 2、3 步继续放在同一页面。
24. 生产根目录必须通过文件夹选择器填写；软件在所选目录自动创建 `frontend`、`backend`、`staging/frontend`、`staging/backend` 与 `backups`，不要求用户手工创建目录。
25. 部署参数应优先从源码推断：Spring Boot 配置推断 Java 端口、`MapHealthChecks` 推断 .NET 健康端点、Vite 配置推断开发代理路径/目标端口、Actuator 依赖推断 Java 健康端点、`web.config` 推断 IIS；无法识别的后端端口默认为 8080 并允许用户修改。
26. 前端默认发布为静态目录以兼容 Nginx；仅当用户选择 IIS 时显示并要求 IIS 站点名。Vite `server.proxy` 只作为路径和端口线索，不能作为生产反向代理。
27. 后端 Windows 服务 ID 必须按 Gerrit 项目名稳定生成，WinSW XML、安装、刷新、启动与回滚由后端 Job 自动执行，不向员工提供服务名输入框。
28. 静态目录/Nginx 模式只显示反向代理提示，不修改 Nginx；IIS 模式只要求站点名、前端端口和后端端口，并自动启用 IIS、创建应用池/站点、设置端口、SPA 回退和接口反向代理。
29. 创建/续建前必须一次性检查全部 Job 的身份、配置与状态；同名未知、运行/排队或已成功脚本改动阻止部署。受管、从未成功的失败任务可经动作清单确认后重试或备份修改；缺失补建、成功部分跳过，后端成功后再部署前端。
30. Java 后端部署必须由用户填写数据库地址、用户名与密码；地址支持完整 JDBC，或基于源码识别到的 JDBC 模板把 `IP:端口` 自动补全为保留数据库类型、库名和参数的完整地址。JWT 密钥为可选项。软件在触发 Jenkins 前原子写入生产目录的 `backend/config/application-prod.yml`，替换前备份旧配置，且不得把这些值写入 Job XML、诊断文件或发布包。
31. 内置 Java 后端服务必须启用 Spring `prod` Profile 并显式加载上述外部配置；配置文件缺失时应在构建环境检查阶段立即失败。.NET 服务固定启用 Production 环境，可选读取生产目录的 `backend/config/appsettings.Production.json`。
32. 只有内置模板且日志证明尚未开始部署时，临时故障才最多整体重试两次；部署开始、证据缺失或自定义 Pipeline 不整体重跑。源码编译/测试失败必须提示用户修复代码；Pipeline 或服务器环境失败必须保留诊断并允许高级用户用完整自定义 Pipeline 替代内置模板。
33. IIS 本体使用 Windows 功能安装，不捆绑所谓 IIS 安装包；URL Rewrite 2.1 x64 与 ARR 3.0 x64 可作为官方离线 MSI 随包携带并复制到持久 Agent 目录。
34. 本地配置在安装中断后缺少 Agent 名称时，软件必须按本机主机名与架构找回唯一的在线 Agent，保存身份并直接进入项目步骤；不得覆盖运行中的 `agent.jar`。
35. 项目识别成功后必须持久化源码根目录；后续启动时若目录存在且仍能识别，自动恢复项目并进入第三步。目录丢失或结构失效时清除旧记录、停留第二步并提示重选，不弹阻塞错误框。
36. 前端 IIS 端口和后端端口输入变化时必须立即尝试绑定本机 TCP 端口；当前可用显示绿色，占用或前后端重复显示红色，空值与非法端口显示中性提示。该结果是部署前提示，Pipeline 执行时仍必须再次校验。
37. 左侧三个步骤上方必须提供统一风格的本机服务看板；只列出本软件生成且安装路径匹配的 `JdaBackend_*` 后端服务，以及使用 `Jda_*` 应用池的 IIS 站点。
38. 看板允许手动启动、停止前后端。停止时必须同步禁止系统自启；后续 Pipeline 部署不得重新启动被手动停止的服务。启动时恢复自动启动并启动服务。
39. “部署成功”弹窗只能在第三步本次预期的 Jenkins 流水线全部成功后显示；看板启停不得复用该成功语义。
40. 服务看板只读刷新不得要求管理员权限；未安装任何受管前后端程序时必须返回空列表而不是弹错。只有启动、停止等状态变更操作需要管理员权限。
41. 看板必须支持删除受管后端服务和 IIS 站点，删除前二次确认且只移除系统注册、保留生产文件；后端服务可通过右键菜单修改显示名称，但不得改变 `JdaBackend_*` 稳定服务 ID。中文界面采用 Windows 中文字体常规字重，避免合成粗体造成毛边。
42. 看板卡片标题不得展示 `JdaBackend_*` 或 `应用池 Jda_*` 类型徽标；删除确认弹窗正文只显示“确认删除吗？”，底层保留文件的安全策略不变。
43. 前端和 .NET 共用打包助手，压缩最多三次、失败间隔 5 秒，持续文件占用仍报错并清理残包；ZIP 完整文件清单绑定项目/构建，压缩后与部署前逐文件核对 SHA-256、长度、数量及必要入口。不得因此重试整个部署，也不增加持锁进程探测。
44. 后端内置 Pipeline 必须把停服务、等待停止、替换产物和失败回滚放在同一异常保护范围内；`Stop-Service` 成功后立即记录状态，失败时只重新启动由本次部署停止的服务。
45. .NET 后端要求 Windows Agent 安装 .NET 10 SDK/Runtime；Restore 关闭并行和构建服务器且最多执行两次，Publish 与 Deploy 不整体重试。入口项目无法唯一确定时必须失败并列出候选，禁止猜测。
46. 前端替换及后续 HTTP 检查失败恢复旧目录；.NET 备份完成前失败不得删除原应用，生产上传/日志目录不得被镜像同步清除。Java/.NET 回滚同时恢复旧服务 XML，健康检查必须纳入回滚保护。JAR 必须唯一、可读、有可执行入口并在部署前复核构建指纹。
47. 已手工安装的 WinSW/Windows 服务式 Agent 必须通过只读服务注册信息和 XML 的 Controller/节点名识别，不要求软件默认目录、命名前缀或 deployment 标签；不得读取 Secret 文件、请求 JNLP Secret、改写原文件或重启服务。离线也保留“已安装”状态并禁止重复配置。
48. 复用外部 Agent 时部署辅助组件使用同盘独立 `JenkinsDeployTool\deployment-support`，不得往原 Agent 目录写入组件；多个候选、其他 Controller 和归属不明时不得猜测或自动重装。
49. 看板必须显示已识别运行项的完整可复制配置地址，IIS包含HTTP/HTTPS所有绑定、域名/IP/端口，后端从既有WinSW监听参数读取；loopback不当作外部地址，无法识别明确提示未知。地址展示不表示连通性或业务健康，不扩大普通手工项目的管理权限。

## 验收场景

### Scenario A：首次启动

- **Given** Windows 主机首次运行软件
- **When** 软件完成本机信息检测
- **Then** 显示 Windows 版本、CPU 架构、主机名、磁盘和明确的下一步，不无限转圈
- **And** 列出全部可用磁盘容量，且未选择磁盘前不能开始安装

### Scenario B：Agent 配置

- **Given** Jenkins URL 与凭据已配置，用户已选择 Agent 安装盘
- **When** 用户点击“一键配置本机 Agent”
- **Then** 在所选磁盘创建唯一 Agent、私有 Java Runtime、agent.jar、公司证书信任库和 WinSW 服务，并启动 WebSocket 验证节点在线

### Scenario B2：先安装 Agent、后安装软件

- **Given** 本机 WinSW 服务已配置 Jenkins Agent，位于任意本地目录，节点名由管理员自定义，软件尚无 Agent 身份配置
- **When** 启动软件或点击重新检测
- **Then** 按本机服务 XML 中的 Controller 与节点名只读确认身份；唯一在线节点直接进入项目选择
- **And** 离线显示“已发现本机 Agent，暂未在线”，不重复安装；多个候选或归属不明明确报错，不猜测
- **And** 不读取 Secret、不写原 exe/XML/JAR/证书、不刷新或启停服务；生产部署组件使用同盘独立软件目录
- **And** WinSW 必须来自软件内置资源，服务器无需访问 GitHub

### Scenario C：项目识别

- **Given** 用户选择一个根目录，源码可能位于任意名称的一级子文件夹中
- **When** 软件扫描目录
- **Then** 根据 `package.json`、Maven/Gradle 构建文件或 `.sln`/`.slnx`/`.csproj` 给出前端、后端子目录和构建工具的可理解确认，不猜测未知生产参数
- **And** 若所选目录只有 `dist`、`.jar` 或 `.dll` 成品，明确列出正确的源码文件要求
- **And** 识别成功后记住源码根目录；下次启动自动重新校验并恢复，目录失效时留在第二步要求重选

### Scenario C2：Gerrit 项目识别

- **Given** 用户输入 Gerrit 项目名
- **When** 输入停止 650ms
- **Then** 软件使用固定地址和固定账号调用 Gerrit REST API，显示识别结果并只读填写仓库地址

### Scenario D：创建 Job

- **Given** Agent 在线、项目识别完成且 Gerrit 项目名已确认
- **When** 用户点击“创建 / 继续部署”
- **Then** 只读检查全部 Job 的身份、配置和构建状态，逐项列出动作并要求确认；未知来源、运行/排队或已成功脚本改动阻止本次操作
- **And** 缺失任务生成独立 Workflow Job，前端只监听前端路径，后端只监听后端路径；首次失败且身份/指纹匹配的任务按下述续建规则处理
- **And** 软件自动触发后端再触发前端，Job 清理旧工作区，从 Gerrit 的 `dev` 分支重新拉取触发版本并完成编译后再部署

### Scenario D2：首次失败后修复并继续

- **Given** 助手已创建 Job，但首次构建因 SDK 等问题失败，且从未有 `SUCCESS` 构建
- **When** 用户修复环境后再次预览并确认继续
- **Then** 不重新创建或静默覆盖原脚本，重新执行失败 Job；已成功部分不重复执行，缺失部分补建
- **And** 新版受管任务允许确认修改失败脚本，修改前完成原配置备份；备份失败不写远程配置
- **And** 旧版仅在原助手描述、当前内置脚本与触发规则一致时可确认认领，不改原脚本；之后仍失败时可按新版规则修改
- **And** 确认后状态/配置发生变化则停止本次操作，绝不停止/取消原构建；全部成功后不再重复首次部署

### Scenario E：浏览长部署表单

- **Given** 项目部署页的自动部署设置超过当前窗口高度
- **When** 用户使用鼠标滚轮、触控板或键盘滚动
- **Then** 右侧内容可以滚动到 Job 预览、确认框和“创建 / 继续部署”按钮
- **And** 顶部栏、左侧步骤栏与底部诊断栏保持可见，页面不产生横向滚动

### Scenario F：三阶段导航

- **Given** 软件正在执行连接、项目识别或创建部署流程
- **When** Agent 上线或项目识别成功
- **Then** 左侧高亮和右侧独立页面自动切换到对应的下一阶段
- **And** 用户可以返回已经解锁的步骤，但不能进入尚未满足前置条件的步骤

### Scenario G：自动部署参数

- **Given** 已识别一个前后端源码项目
- **When** 进入创建部署页
- **Then** 软件自动填写前端发布方式、后端端口、健康检查和稳定的 Windows 服务名，只显示仍需确认的参数
- **And** 首次后端 Job 自动安装 WinSW 服务，以后幂等更新并重启同一服务

### Scenario H：生产环境配置

- **Given** 已识别包含 Java 后端的项目并选择生产根目录
- **When** 用户填写完整 JDBC 或 `IP:端口`、用户名、密码以及可选 JWT 密钥并确认部署
- **Then** 软件在 `backend/config/application-prod.yml` 写入 Spring Boot 生产配置，已有文件先备份到 `backups/config`
- **And** `IP:端口` 会基于源码 JDBC 模板自动补全；JWT 留空时不生成 JWT 配置段
- **And** 密码与密钥不进入 Jenkins Job、自定义诊断或版本压缩包，WinSW 以 `prod` Profile 启动并加载外部配置
- **And** 页面明确说明生产反向代理由 Nginx/IIS 完成，Vite 代理仅用于开发

### Scenario H2：.NET 10 后端部署

- **Given** 已识别包含 .NET 后端的项目且 Agent 安装 .NET 10 SDK/Runtime
- **When** 后端 Job 执行
- **Then** 唯一选择可部署项目，Restore 最多两次后执行框架依赖型 Publish，并由 WinSW 以 Production 环境启动
- **And** 构建 ZIP 排除生产配置、上传目录和日志；部署失败恢复旧应用与本次部署前的服务状态
- **And** 多个入口无法唯一判断时停止并列出候选，不继续部署

### Scenario H：全自动 IIS

- **Given** 用户选择 IIS，输入站点名、前端端口与后端端口
- **When** 首次前端 Job 执行
- **Then** 检查管理员权限和端口冲突，启用 Windows IIS 角色，按需从 Agent 目录安装 URL Rewrite 与 ARR
- **And** 自动创建或更新应用池、站点、物理目录、HTTP 绑定、SPA 回退和 `/api → 127.0.0.1:<后端端口>` 规则
- **And** 不自动配置 HTTPS、域名或证书

### Scenario I：端口占用提示

- **Given** 用户正在填写 IIS 前端端口或后端服务端口
- **When** 端口输入发生变化
- **Then** 软件立即检测本机 TCP 端口，可用时显示绿色说明，被其他进程占用时显示红色说明
- **And** 前后端填写相同端口时两处都显示红色冲突说明，非法端口显示中性输入提示

## 已知边界

- 当前自动适配 Node.js 前端、Maven/Gradle 可执行 JAR 后端和 Windows Agent 上的框架依赖型 .NET 10 后端；.NET 自包含/AOT 与其他语言暂不自动适配。
- 源码中不存在明确端口、代理或健康检查配置时使用安全默认值并允许确认；Nginx 不自动修改，IIS 只管理用户明确指定的站点。
- 软件可在上线后删除本机一次性注册字段；服务器端短时过期与吊销需要额外的凭据签发服务，Jenkins 原生账号密码不能由客户端变成真正的一次性凭据。
- 首次上线和真实生产发布必须先在隔离测试环境验证。

## 非功能要求

- 交互反馈 100ms 内可见；网络操作有超时、阶段与重试入口。
- 同一按钮执行期间禁止重复提交；创建节点按名称幂等。同名未知/正常运行 Job 禁止覆盖；助手管理且从未成功、未运行/排队的任务可在操作清单确认后继续或备份修改，已成功部分跳过。旧版必须符合原描述及当前内置模板/触发规则才能确认认领，身份不明时失败关闭。
- 日志只记阶段、状态、耗时和脱敏错误，不记录密码、Token 或 Agent Secret。
- 主窗口面向 1024×720 及以上 Windows 桌面，支持键盘 Tab 和可见焦点。
